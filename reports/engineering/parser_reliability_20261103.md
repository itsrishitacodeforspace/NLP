## Defects found and fixed by this suite

1. `strip_headers_footers` stripped clause *body* lines containing 'confidential'/'draft' (e.g. "Confidentiality is paramount."). Fixed: a hint line must be <= 60 chars; 'Page N of M' is stripped at any length.
2. An image-only (scanned) PDF raised the generic "no text… empty or corrupted" message *before* the OCR gate, so the tesseract hint never surfaced. Fixed with `_raise_no_extractable_text`: multi-page / OCR-attempted PDFs raise with the hint.
3. Mixed-case annexures (`Annex 2: …`) were not detected as clause headings. Fixed with `_ANNEXURE_HEADING_RE` (annexure/annex/schedule/exhibit/appendix at line start).
4. `_stamp_page_hints` used `doc.find(pg.text)` (first occurrence), so a page whose text re-appeared earlier (the ANNEXURE A heading is also inside clause 4's body) shifted all later bounds and left the final page's clause with `page_hint=None`. Fixed: search forward from the previous page's end.

## Limitations

- **OCR is not installed** in this container (`which tesseract` -> not found), so the scanned-PDF path is verified only as a *graceful failure* with the tesseract hint, not as a successful OCR extraction.
- pdfplumber emits occasional cosmetic mid-word line breaks (e.g. `stateme\nt`) on lines near the right margin; these do **not** violate the slice invariant (offsets remain exact) and do not change clause boundaries, but the raw extracted text is not byte-identical to the source.
- `char_start/char_end` index the *cleaned* text (NFKC + whitespace collapse), not the raw file bytes; original-document highlighting would need a cleaned->raw offset map (documented design caveat, audit 2.3).
