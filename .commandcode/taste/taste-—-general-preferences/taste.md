- Prefers `uv` as the primary Python environment/runner, with `.env`/venv as a fallback ("i would go first with uv then others"). Confidence: 0.8
- Wants a continuous, timestamped memory/thought journal kept as work proceeds, recording what was examined and concluded — not just a final summary. Confidence: 0.7
- Wants the assistant to adhere strictly to the explicit workflow/protocol the user lays out (e.g. context-collection mode), rather than deviating to run its own commands or expand scope unprompted. Confidence: 0.65
- Prioritizes never risking existing files/data/artifacts: do not modify code before approval, preserve existing repo state, and propose a safe isolated method (e.g. an exported copy) instead of running potentially destructive operations like clean-clone/reset. Confidence: 0.75
- Wants changes developed test-first and kept minimal: land a failing regression test before each fix, then the minimal implementation, then the passing test — rather than broad refactors. Confidence: 0.7
- Expects evidence-grade reporting from real runs — exact command, exit code, complete output, and input/artifact identities — and no overclaiming (e.g. don't call results a benchmark unless the split actually supports it). Confidence: 0.7
- Wants source/identity validation to be independently verifiable: don't trust a caller-supplied label (e.g. `split="train"`), but validate against an explicit manifest/allowlist with recorded hashes. Confidence: 0.7
- Prefers fail-closed behavior over silent degradation: a required test or evaluation command should fail (non-zero, with a clear message) when its required inputs or provenance are missing or inconsistent, rather than skipping silently or only warning; and a finding should not be suppressed on weak or indirect evidence (e.g. keyword presence in a related clause, reference resolution alone) — require specific supporting contract evidence before suppressing. Confidence: 0.7

- Requires tests to be isolated and side-effect-free: use temporary fixtures where feasible, never mutate repository datasets, rewrite generated/data directories, extract archives, or contact external services — and call out any unavoidably impure operation before proceeding. Confidence: 0.7
- Distrusts sampled/partial checks for correctness verification: when an invariant is meant to hold over a corpus (e.g. leakage/overlap checks), verify the full population rather than an ordering-dependent prefix or subset. Confidence: 0.55
- Wants an explicit file-scope allowlist for a change (every permitted added/modified path enumerated), and wants the plan document plus that allowlist updated and returned for approval *before* any editing begins — then the actual worktree diffed against the list afterwards with any unexpected paths reported. Confidence: 0.7
